# SoraChat

iPad・スマホ向けのチャットアプリです。LINE に近い見た目と操作で、トーク（1対1・グループ）、友だち、リアクション、返信、24時間ノート、プロフィールを備えます。データベースは Supabase のみを使い、Supabase Auth は使いません。

## 機能

- ログイン：仙人アカウントで続行、またはユーザー名とパスワードで登録・ログイン
- 画面：下のタブで「トーク」「友だち」「その他」を切り替えます
- トーク：1対1とグループ（テキスト・画像・ファイル・連絡先、リアクション 👍 ❤️ 😂 😮 😢 🙏）
- 友だち：ユーザー名の検索かQRコードで追加します。友だちの削除もできます
- グループ：友だちの中から選んで作成・メンバー追加します（友だち以外は入れられません）。管理者が名前変更・メンバー削除、全員が退出
- 新規トーク：友だちを選んで1対1で話す、またはグループを作成
- ノート：60文字まで、24時間で消える一言。相手のプロフィールに表示
- 返信・メニュー：吹き出しをダブルタップするとメニューが開きます（返信・コピー・編集・送信・取り消し）。返信は入力欄の上に返信先を出し、吹き出しの上に引用を表示します
- 通知：新着トークのWeb Push（オン・オフ可）。画面を見ている間は出さず、裏に回したときや閉じているときに届きます
- プロフィール：LINE風（背景の色、アバター、ステータスメッセージ、ノート、QRコード）
- アニメーション：画面の切り替え、シート、吹き出しの出現、ハートの浮き上がり、タブ、未読バッジなどに動きを付けています（端末の「動きを減らす」設定では最小限になります）
- 初回起動：ウェルカムの動きのあと、機能紹介（スワイプ可）を出します。見終わると自動では出ません。ログイン画面の「機能紹介を見る」からもう一度見られます（ブラウザーに記録します）
- ログイン：背景・ロゴ・入力欄のアイコン、パスワードの表示切り替え、入力条件のヒントを付けています（処理内容は変わりません）
- ファイル：PDF と .txt / .md / .csv / .log / .json は、トークの中で全画面表示できます（タップで開く）。それ以外のファイルはこれまで通りタップでダウンロードします
- 投票：LINE に近い形です。複数選択・匿名投票に対応し、吹き出しの「結果を見る」（または吹き出しのタップ）で全画面の投票画面を開きます。投票画面では票の割合と、誰が選んだか（匿名のときは非表示）を確かめられます。作った人だけ「投票を締め切る」ができ、締め切ったあとは選べません

## サーバー負荷について

- 新着はポーリングせず、Supabase Realtime（postgres_changes）で受け取ります。
- 送信・リアクション・メンバー操作だけがAPIリクエストになります。
- 未読などの一覧は、イベントを受けたときにまとめて再取得します（連続イベントは0.4秒まとめます）。保険として2分ごとにも再取得します。

4. `npm install` のあと、開発は `npm run dev`、本番は `npm run build` → `npm start` です。

## senninai（AIチャット）

設定の「AI」で「senninai（AIチャット）」をオンにすると、トーク一覧にロボットのアイコンの「senninai」が出ます（既定はオフ。オフにすると一覧から消えます）。回答は UserLocal の senninai API（`SENNIN_AI_URL`、既定は作者の公開エンドポイント）から取ります。

- **トーク（senninai）**: 話しかけるとAIが答えます。言い回しは自由です。
  - 読む・要約・質問: 「太郎とのチャットを読んで要点を教えて」「太郎と何を話したか見てくれる？」（直近20件のトーク、約6000文字分をもとに答えます）
  - 返信案: 「太郎への返信を考えて」（返信案を3つ出します）
  - 送信: 「太郎に『明日遅れます』と送って」。送る前に「はい／いいえ」の確認画面を出します。「この内容を送って」は直前に自分が書いた文章を送ります。
  - 決まった言い回しに当たらないものは、AIに「何をしてほしいか」を判定させます（判定に失敗したらふつうの会話として答えます）。
- **グループ**: `/senninai add` でsenninaiが参加し、`/senninai ask 質問` で質問できます（参加していないと使えません）。
  - 人について聞けます: 「/senninai ask 太郎のことどう思う？」。その人の直近の発言だけを根拠に、中立に答えるよう指示しています。
  - 「まとめて」「決まったこと」などの要約系の質問は、やや広めに直近の会話を読みます。
- 送信や読み取りの対象は、自分のトークと友だちの中から名前で探します。候補が複数あるときは確認を求めます。
- 注意: 話しかけた内容や読んだトークの内容は、AIの応答のために外部サービス（UserLocal）へ送られます。使う人は設定の注意書きを確認してください。
- 注意: 確認待ちの送信は `sc_senninai_pending` テーブルに5分間だけ保存します。
- 注意: 判定のために、ルールに当たらない発言ごとにAIへ1回余分に問い合わせます（応答が少し遅くなります）。
- 注意: 「senninai」は予約されたユーザー名です。`schema_v12.sql` を実行する前に同じ名前の人がいる場合は、その人の名前を先に変えてください。
- `schema_v12.sql` は後から確認待ちのテーブルを足しています。すでに実行済みでも、もう一度実行してください（何度実行しても安全です）。

- **クイズ（ミニゲーム）**: グループの「早押しクイズ」は、開始のたびに senninai が4択の問題を5問作ります（テーマと選択肢の順番は毎回ランダム）。AIが応答しない・形式が合わないときは、固定の問題（`server/gameLogic.ts` の `QUIZ_BANK`）で続けます。作成は `server/quizgen.ts` です。

## 仙人ストア（ポイントで買い物）

- 商品の一覧・価格の初期値は `server/storeCatalog.ts` にあります。運営は管理者パネルの「ストア・Pay」→「ストアの商品」から、名前・説明・価格・スタンプの中身・販売の有無を変えられ、スタンプパックも追加できます（`sc_store_overrides` に保存して、コードの変更なしで反映）。
- 自分の作品も買えます。その場合、ポイントは作者ではなく運営（`OPERATOR_USER_ID`）に入ります。運営の設定がないと、自分の作品は買えません。
- ログイン特典：`SENNIN_LOGIN_BONUS=on` のとき、仙人アカウントでログインした人に1人1回30ptを付けます（ログイン時にポイントの許可も求めます。仙人側で `points:write` の承認が必要です）。

- 「その他」→「仙人ストア」（専用ページ `/store`）から、仙人アカウントのポイントで次を買えます。
  - **外観**: 自分の吹き出し・背景・アクセント色を変えます（自分の画面だけに出ます）。
  - **スタンプパック**: パックを買うと、そのスタンプを送れるようになります（買う前の送信はサーバーでも断ります）。
  - **拡張機能**: 「senninai をグループに入れる」「ミニゲーム：じゃんけん大会」「ミニゲーム：数当て」。買うまでは使えません。
- 「その他」→「拡張機能」（`/extensions`）: 買った拡張機能を「開く」で起動します。買った外観を「使う」で選び、「標準に戻す」で既存の見た目に戻せます（外観の選択は仙人ストアと同じ API を使います）。
- 仙人アカウントと連携していない人には、ストアの画面で先に連携を案内します。ユーザー名・パスワードで作ったアカウントにも、そのまま連携できます（1つの仙人アカウントは1つのアカウントにだけ連携できます）。
- 商品の一覧・価格は `server/storeCatalog.ts` にあります。値段の変更や商品の追加は、そこを編集するだけで反映されます。`price: 0` の商品は無料扱いです。
- 購入の流れ: 購入の記録を作る → 仙人アカウントでポイントを減らす（`idempotency_key` は購入ごとに一意）→ 商品を持たせる。通信が途切れたときは、同じ購入として確かめ直すので二重に払いません。
- 連携の更新トークンは `MESSAGE_ENCRYPTION_KEY` で暗号化して `sc_sennin_tokens` に保存します。連携はストア用の許可（`SENNIN_STORE_SCOPE`）で行い、ログインのみの許可とは別です。
- 注意: `points:write`（ポイントの加算・減算）は、仙人アカウント側の管理者の承認が必要です。承認されていないと、連携の画面で「許可されませんでした」と表示されます。
- 注意: `supabase/schema_v26.sql` の実行が必要です。

## SenninPay（友だちへの送金・店舗のQR払い）

- 「その他」→「SenninPay」（`/pay`）から、仙人アカウントのポイントを使えます。送る・スキャン・受け取る・店舗・取引履歴があります。
- **友だちに送る**：友だちにだけ送れます。送った人の残高が減り、受け取る人の残高が増えます。受け取れないと分かったときは自動で返金します。
- **QRで払う**：店舗のQRを読み取り、金額を入れて支払います（1〜10,000pt）。
- **店舗**：申請すると、その場でQRが発行されます（審査はありません。運営は停止・再開できます）。店舗も仙人アカウントと連携している必要があります。
- 送金は `sc_pay_transfers` に記録し、途中で止まった送金は履歴を開いたときに続きから進めます（同じ送金キーで再送するので二重には動きません）。
- 注意: `supabase/schema_v29.sql` の実行が必要です。実機での動作確認は未実施です。
- 画面は PayPay のような構成です（残高 → スキャン・送る・受け取る・店舗 → 最近の取引）。QR は友だちのQR（送金）も店舗のQR（支払い）も、同じ「スキャン」で読み取れ、「送る」の画面からもQRで送れます。「受け取る」には自分のQRを出します。友だちへの送金は、これまでどおり友だちにだけ送れます。
- 検査: `npm run test:pay`（送金の状態遷移・返金・再送の冪等性、スタンプと商品の検査、店舗QR。仙人アカウントはスタブで再現します）。

## senningames（1人で遊んでポイントをためる）

- 「その他」→「senningames」（`/senningames`）から遊べます。1ラウンドは30秒です。
- ゲームは4つです。1つあたりのポイントは、サーバーの `server/senningames.ts`（`SOLO_GAMES`）で決めています。
  - 風船割り: 1個 0.03pt
  - もぐらたたき: 1匹 0.02pt
  - ストップ: 1回 0.05pt
  - 神経衰弱: 1組 0.1pt
- 結果は、ラウンドの終わりか「やめる」を押したときに、遊んだ数だけを送って加算します（ポイントの計算はサーバーでします）。同じゲームは20秒以上あけないと続けて加算されません。
- たまったポイントは 200pt ずつ、仙人アカウントのポイントへ出金できます（仙人アカウントとの連携が必要です）。出金は同じ出金IDで押し直しても二重にはなりません。
- 注意: `supabase/schema_v31.sql` の実行が必要です。加算・出金は、DB の関数（`sc_solo_reward` など）で1つのまとまりとして行います。
- 注意: 遊んだ数は画面から送るので、悪意のある操作を完全には防げません。ラウンドの上限（`maxPerRound`）と間隔で、加算できる量を抑えています。

## senninstudio（作者向けの作品販売）

- 「その他」→「senninstudio」（専用ページ `/studio`）から、作品を公開して、ポイントで売れます（手数料なし。購入額が全額、作者の仙人アカウントに入ります）。
- 作品の種類は次の5つです。
  - **スタンプパック**: 1〜24枚（PNG・GIF・WebP、縦横16〜512px、1枚1MBまで）
  - **外観**: 吹き出し・背景・ボタンの色（#RRGGBB）
  - **クイズ**: 4択の問題を5〜50問（対戦で5問ずつ出題されます）
  - **応答スタイル**: senninai の口調・長さ・絵文字の使い方（選択肢だけ。自由文の指示は入りません）
  - **拡張機能**: HTML・CSS・JavaScript で作るミニアプリ（HTML 6万字・CSS 6万字・JavaScript 15万字まで）。買った人は、ストアの掲載ページの「開く」から全画面で使えます。
- 価格は 10〜1,000 pt。作者は仙人アカウントを連携した人だけ。1人1日20作品まで。
- **審査はありません。** 公開時に自動で確かめます。URL・メールアドレス・電話番号らしいもの・禁止語（`server/studioRules.ts` の `BLOCKED_WORDS`）は公開できません。画像は中身で形式と大きさを判定します（拡張子は信用しません）。
- 通報: 買った人や見た人は、ストアの作品から通報できます（1人1回）。**通報が5件たまると自動で非公開**になります。
- 作者ができるのは「公開」「編集」「削除」です。削除しても、すでに買った人は引き続き使えます。
- **編集**: 名前・説明・価格・サムネイル・中身（外観の色、クイズの問題、応答スタイル）は、公開後も変えられます（買った人の画面にも反映されます）。スタンプ画像と作品の種類は、買った人の手元に残るため変えられません（作り直して公開します）。
- **レビュー**: その作品を買った人だけが、星 1〜5 とコメント（1000文字まで）を付けられます。作者本人は付けられません。1人1作品1件で、あとから直したり消したりできます。コメントも、URL・連絡先・禁止語は自動で止めます。
- **作者の評価**: 作者の全作品のレビューの平均です。作者のページ（`/store/author/:id`）で見られます。
- **掲載ページ**: 商品をタップすると、概要・レビュー・作者のタブのある掲載ページ（`/store/item/:id`）を開きます。星の集計（平均と星ごとの件数）と、レビューの投稿・編集・削除もここで行います。
- **開発者ダッシュボード**: 「その他」→「senninstudio」（`/studio`）は、概要・作品・レビュー・支払い・ドキュメントのタブを持つ開発者画面です。作品の作成（`/studio/new`）と編集（`/studio/works/:id/edit`）は、公開前チェックを見ながら行えます。
- 管理者パネルの「作品」タブから、作品の公開・非公開・削除、通報の確認と記録の消去、作者の停止（停止すると販売中の作品も非公開）、支払いの確認と再送ができます。
- 支払い: 購入のたびに、作者への支払いを1件作ります。作者が仙人アカウントを連携していない・権限がない間は保留にして、連携したときに自動で払います。払えないときは管理者が再送できます。支払いごとに `idempotency_key` を付けるので、二重には払いません。
- 注意: 管理者の削除で作品の画像を消すと、買った人のスタンプも表示されなくなります（返金は行いません）。
- 注意: `supabase/schema_v27.sql` と `supabase/schema_v28.sql` の実行が必要です（v29 以降の変更は上の「ストア」「SenninPay」の項を参照）。
- 注意: 編集・レビューの API は `server/studioReviews.ts`（レビュー・作者のページ・掲載ページ）と `server/studio.ts`（作品の編集・支払いの一覧）にあります。

### 拡張機能の安全のしくみ

作者が書いたコードは、ソラチャットの画面の中では動かしません。

- 表示は `GET /api/studio/extensions/:id/frame`（買った人と作者だけ）が返す文書を、`<iframe sandbox="allow-scripts">` で開きます。`allow-same-origin` は付けないので、中のコードは別の出どころ扱いになり、ログイン情報（Cookie）・画面・`localStorage` に触れません。
- 文書には CSP（`sandbox allow-scripts; default-src 'none'; connect-src 'none'; …`）も付けています。外のサイトへの通信・外部の読み込み・別ページの埋め込みはブラウザが止めます（`server/studioRules.ts` の `EXTENSION_CSP`）。
- 公開前の自動チェックでも、外部サイトのURL・`fetch` など通信・`iframe`/`embed`/外部 `script`・親ページへのアクセスを止めます（最後の守りは上の sandbox と CSP です）。
- 作品の中身（コード）は、掲載ページには出しません（大きさだけ）。買った人と作者だけが動かせます。
- 編集画面の「試し表示」は `POST /api/studio/extensions/preview`（保存しない）で、本番と同じ隔離の枠で確かめられます。
- 検査: `npm run test:studio`。
- 注意: `supabase/schema_v30.sql` の実行が必要です。

### 拡張機能からポイントを配る（ブリッジ）

枠の中の拡張機能は、サーバーへ直接は通信できません。代わりに `window.sorachat` で、ソラチャットの画面に頼みます。ソラチャットの画面が依頼を確かめて、サーバーへ取り次ぎます。

- 拡張機能を開くと、先に「アカウント情報の許可」の確認（下から出るシート）が出ます。許可するまで枠は開きません。許可したアカウントの情報（ユーザー名・表示名・ID、仙人アカウントの連携の有無と仙人ID）だけを、拡張機能に渡します。許可は「許可を取り消して閉じる」からいつでも取り消せます。
- `window.sorachat.awardPoints(amount, reason, requestId)` で、許可した本人に仙人アカウントのポイントを配ります。配れる量は、**管理者が拡張機能ごとに決めた上限**の中だけです（管理者パネル → 作品 → 「ポイントの配布の上限」）。上限を超えると 409 で断ります。作者は上限を変えられません。
- 1人が1分間に受け取れるポイントの上限（`per_user_minute_max`。0 は制限なし）も、管理者が拡張機能ごとに決めます（超えると 429・code: `minute_limit`）。
- 配布は `POST /api/studio/extensions/:id/award` で行い、枠の確保（`sc_extension_reserve`）と記録は DB の関数で1つにまとめます。`requestId` が同じなら二重には配りません。仙人アカウントへの加算は `idempotency_key`（`ext-award-配布ID`）で行います。
- 開発者向けの仕様は、senninstudio の「ドキュメント」タブに出ます（`GET /api/studio/extensions/spec`）。上限・窓口の名前・エラーの code は、サーバーの定数（`EXT_BRIDGE` と `server/extensionPoints.ts`）から自動で作られるので、文書を手で直す必要はありません。AI に渡すときは、その文書をコピーしてください。
- 注意: `supabase/schema_v33.sql` と `supabase/schema_v35.sql` の実行が必要です。
- 検査: `npm run test:extension-points`（ブリッジの構文・仕様の内容）。配布の枠の関数は、PostgreSQL で確かめ済みです。

## 画像・ファイルの保存先（Turso）

プロフィールアイコン・グループのアイコン・トークの画像とファイル・senninstudio の画像は、すべて Turso（`sc_blobs`）に保存します（`TURSO_DATABASE_URL` / `TURSO_AUTH_TOKEN`）。Cloudflare Images の設定（`CLOUDFLARE_*`）は不要になりました。以前に Supabase Storage へ保存した画像は、読み込みだけ残しています。

## ブロック・通知・トークの削除

- **ブロック**: 相手のプロフィールの「ブロックする」。友だちと申請は両方向とも消え、1対1のトークは両方向とも送れなくなります。ブロックした側には、その人の発言が届かず、履歴にも出ません（グループは残ります）。解除は相手のプロフィールか「設定」の「ブロック」から。
- **トークごとの通知**: トークの右上の設定ボタンから「このトークの通知」をオフにできます。オフでもトークの未読数は残ります。通知（Web Push）だけ届きません。
- **トークの削除**: 1対1は「トークを削除」で自分の画面からだけ消えます（相手の画面には残ります）。グループは「退出してトークを削除」。最後の1人が抜けると、メッセージ・リアクション・画像・ファイルを完全に消します（転送で別のトークと共有している画像は残します）。
- 注意: 1対1で相手だけが残っている間は、相手の画面にあなたのメッセージが残ります。相手のトークは、あなたの操作では消せません。

## グループ電話

- グループのトーク画面の右上の電話ボタンで、同じグループの全員に着信を送ります（応答で参加、退出で抜けます）。
- シグナリング（呼び出し・接続情報）は Supabase Realtime の broadcast で行い、音声は参加者どうしの WebRTC（メッシュ）で直接つなぎます。Render のサーバーは音声を中継しません。
- 人数は最大6人です。接続は STUN のみを使うため、厳しい NAT の回線では繋がらないことがあります（TURN サーバーを追加すると改善します）。
- 呼び出しは、アプリを開いている相手にだけ届きます（閉じている相手へのプッシュ通知はありません）。
- 呼び出しは `POST /api/calls` でサーバーが送ります（1人あたり10分に8回まで）。シグナリングは通話ごとの鍵で署名します。
- 注意: `supabase/schema_v22.sql` と `supabase/schema_v23.sql` の実行が必要です。実機での動作確認は未実施です。
- 通話の「〇〇さんが参加しました」「退出しました」「通話が終了しました」のお知らせは出しません。トークには「電話に参加」のカードだけが残ります。

## オープンチャット・管理者パネル

- オープンチャット：「その他」→「オープンチャット」から、誰でも一覧を見て参加できるグループを作れます（友だちでなくても参加可能）。
- 管理者パネル：`/admin/login` から `ADMIN_PASSWORD` でログインします。一般の画面には入口を出していません。

  - 利用停止にすると、そのユーザーはログインできず、既存のログインも切れます。
- 管理者のログインは12時間で切れます。パスワードを忘れた場合は環境変数 `ADMIN_PASSWORD` を変えてください。

## メンテナンスモード・稼働状況

- **メンテナンスモード**: 環境変数 `MAINTENANCE_MODE=on` で有効になります。利用者向けの画面と API、WebSocket を止めて「メンテナンス中ですしばらくお待ちください。」を表示します。開いたままのアプリも、次の操作でこの表示に切り替わり、終わると自動で読み直します。
  - 切り替えは環境変数の変更（サーバーの再起動）で反映されます。空または `off` で通常どおりです。
  - 表示する文言は `MAINTENANCE_MESSAGE` で変えられます（空なら既定の文言）。
  - 止めないもの: `/api/health`（ヘルスチェック）、`/api/status` と `/status`（稼働状況）、管理者パネル（`/admin`、`/api/admin`）。
- **稼働状況のページ**: `/status` で、機能ごとの状態を見られます。表示は、サーバーが実際に行った確認の結果だけです（固定の「正常」表示はありません）。
  - データベースの各テーブルへの問い合わせ、Turso・Supabase Storage への問い合わせ、仙人アカウントの認証サーバーと senninai の接続先への接続を試します。
  - 通知の鍵・管理者パスワードは設定の有無だけを見ます（配信やログインは試しません）。リアルタイム接続は、この確認では試していません（「未確認」と出ます）。
  - 結果は30秒のあいだ保持します。JSON は `GET /api/status` で取れます。

## 注意点

- ログインは、仙人ストア・senninstudio のマイグレーション（v26・v27）が未実行でも使えます（ストアの情報は読めなければ省きます）。
- 仙人アカウントでのログインボタンは、`SENNIN_CLIENT_ID`・認可URL・トークンURL・リダイレクトURI がそろっているときだけ表示します（`GET /api/auth/options`）。認可URL・トークンURLなどは、`SENNIN_BASE_URL`（例: `https://account.example.com`）を1つ設定すれば自動で決まります（個別の `SENNIN_*_URL` を入れた場合はそちらが優先）。
- 「仙人アカウントは現在利用できません。」と出るときは、サーバーのログに `[sennin] 仙人アカウントの設定が足りません: ...` と、足りない環境変数の名前が出ます。`SENNIN_CLIENT_ID` を入れていても、`SENNIN_BASE_URL`（または `SENNIN_AUTHORIZATION_URL`・`SENNIN_TOKEN_URL`）が空だと出ます。環境変数を変えたあとはサーバーの再起動が必要です。
- 環境変数の値は、前後の空白・改行・引用符を自動で取り除きます（ホスティングの画面に貼り付けたときの混入対策）。`SENNIN_REDIRECT_URI` は、仙人アカウントの開発者設定に登録したリダイレクトURIと完全一致させてください。
- 仙人アカウントとの連携は、仙人ストア・senninstudio を使うときだけ必要です。通常のログインには不要です。

- iOS で通知を受けるには、Safari でホーム画面に追加して、そのアプリとして開く必要があります。通知の許可は、設定のスイッチを押した直後に求めます。
- 通知の購読は、アプリを開くたびに確かめ直します（許可済みの端末のみ）。
- 設定の「テスト通知を送る」で、登録済みの端末すべてに通知を送り、届いたかどうかを確かめられます。届かないときは結果の理由が表示されます。
- 通知は端末ごとに判定します。画面を開いている端末には出さず、ほかの端末（閉じているスマホなど）には出します。
- 通知がオフのときは「通知をオンにしますか？」を出します（「あとで」を押すと3日間は出しません）。
- グループのアイコンは管理者だけが変更できます（名前の変更と同じ条件）。
- ログイン試行は1分あたり20回までに制限しています。この制限はプロセス内の記録なので、複数インスタンスでは共有されません。
- ロゴとアイコンは SoraLink の流用です。`public/icons/icon-180.png` を差し替えてください。
- 旧版（DMだけのバージョン）の既存データは、そのまま使えます。schema_v2 は既存テーブルに列を追加するだけです。

## メッセージの暗号化

- メッセージ本文と一覧のプレビューは、DBに保存する前に AES-256-GCM で暗号化します。DBには暗号文だけが入ります。
- 鍵は環境変数 `MESSAGE_ENCRYPTION_KEY`（32バイトの乱数を base64 にしたもの）です。作成は `openssl rand -base64 32`。
- **鍵を変えたり失くしたりすると、既存のメッセージは読めなくなります。** 鍵は安全な場所に控えてください。
- 鍵がない場合、サーバーは起動しません（平文で保存されないようにするため）。
- admin パネルでは、今まで通りチャット内容を見られます（サーバーが復号するため）。
- 導入前に保存された平文は、`npm run encrypt:backfill` で暗号化できます。何度実行しても安全です。
- プッシュ通知の本文には、メッセージの内容を載せません（「新しいメッセージがあります」）。
- 画像・ファイルの中身は、この変更では暗号化していません（別途対応が必要です）。
